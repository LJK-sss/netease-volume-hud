# 探针验证结论（2026-10-24）

## 一、环境

- Windows 11 25H2 / build 26200（注册表 ProductName 仍写 Windows 10，属正常）
- .NET Framework 4.8.1（`csc.exe` 4.8.9221 可用）→ 可直接编译单文件 exe，零安装
- 网易云：`D:\CloudMusic\cloudmusic.exe`，同时存在 3 个进程，音频会话属于 **pid 1724**
- 默认渲染设备 `{0.0.0.00000000}.{f9fb4b7a-...}`，共 4 个活动设备

## 二、结论总表

| 项 | 结论 | 依据 |
|---|---|---|
| 按进程定位音频会话 | ✅ 可用 | `IAudioSessionControl2::GetSessionIdentifier` 含 exe 路径，可按 `cloudmusic.exe` 匹配（不依赖进程枚举） |

| 窗口标题读歌名 | ✅ 可用 | 隐藏主窗口 `OrpheusBrowserHost` 标题 = `歌名 - 歌手`，切歌实时更新 |
| UIA 读网易云内部控件 | ❌ 不可用 | 三个窗口 UIA 后代数均为 0（自绘界面） |

| **进程级环回抓流** | ✅ **可用** | 见第三节 |
| 进程隔离性 | ✅ 已验证 | 抓网易云 = -30.4 dBFS；抓静音的游戏/微信 = -96.7 dBFS。若泄漏成设备混音，三者应同为 -30 dBFS |

## 三、关键坑：`ActivateAudioInterfaceAsync` 返回 `E_UNEXPECTED`

**现象**：文档标准用法（NULL 参数 + 真实设备 ID）也返回 `0x8000000E`。

**根因**：`completionHandler` 必须实现 **`IAgileObject`**（agile 对象）。
缺少时 Windows 返回**误导性**的 `E_UNEXPECTED`，而非文档所说的 `E_ILLEGAL_METHOD_CALL`。

**验证矩阵**：

| 变体 | HRESULT |
|---|---|
| handler=NULL | `E_INVALIDARG`（参数校验在最前） |
| 普通 handler + 合法路径 | `E_UNEXPECTED` |
| 普通 handler + 垃圾路径 | `E_UNEXPECTED`（说明失败早于路径解析） |
| x86 编译 | `E_UNEXPECTED`（与位数无关） |
| STA 线程 + 消息泵 | `E_UNEXPECTED` |
| 带 HWND 的 STA 线程 | `E_UNEXPECTED` |
| **agile handler** | ✅ **S_OK** |

**修复**：`class X : IActivateAudioInterfaceCompletionHandler, IAgileObject`
其中 `IAgileObject` = `94EA2B94-E9CC-49E0-C0FF-EE64CA8F5B90`（空标记接口）。

## 四、信号链路位置（受控测试音，440Hz，振幅 12000/32768 = -8.73 dBFS）

| 会话音量 | 实测 RMS | 实测峰值 |
|---|---|---|
| 100% | -11.8 dBFS | **-8.7 dBFS** |
| 50% | -17.8 dBFS | -14.7 dBFS |
| 25% | -23.8 dBFS | -20.7 dBFS |

推出两个重要性质：

1. **测量值与源振幅完全一致** → 测量链路精确，无隐藏增益
2. 每次降半档正好 -6.0 dB → **抓流点在会话音量之后**（增益闭环、可验证）
3. 系统音量 30% 未体现在读数中 → **抓流点在系统音量之前**（自动增益不受系统音量影响）

## 五、配平（用户已同意）

现状：系统 30% × 会话 100% × 内部 32% → **会话音量无任何上调余量**。

配平：内部 32% → 80~100%，会话 100% → 32%
- 听感不变（9.9 dB 增益与 9.9 dB 衰减抵消）
- 腾出 **20·log10(100/32) = 9.9 dB** 的自动补偿空间
- 削波余量：网易云峰值实测 **-21.5 dBFS**，抬 9.9 dB 后约 **-11.6 dBFS**，仍有余量，不会削波

## 六、对实现方案的最终影响

1. 歌名来源：窗口标题（`歌名 - 歌手`），不用 SMTC
2. 配平：必须手工做一次（UIA 无法读写内部滑块）
3. 自动增益：用进程级环回抓流 + 闭环控制（测量含我们施加的增益，注意避免振荡）
4. 响应：抓流缓冲 20ms，控制周期建议 200~300ms
